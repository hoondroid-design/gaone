# 무용가 공식 홈페이지 — 설치와 운영 안내서

이 저장소는 GitHub Pages(화면)와 Firebase(데이터, 로그인, 이미지)로 동작하는 무용가 홈페이지입니다.
처음부터 끝까지 따라 하면 **전용 도메인 + 관리자 2단계 인증 + (선택) 이메일 알림**까지 갖춘 사이트가 됩니다.

> 메뉴 이름이나 화면 배치는 Google, GitHub, 도메인 업체 사정에 따라 조금씩 바뀔 수 있어요. 비슷한 이름의 메뉴를 찾으면 됩니다.

## 파일 구성

```
├─ docs/                  ← GitHub Pages로 공개되는 사이트 (화면)
│  ├─ index.html          사이트 전체 (방문자 화면 + 관리자 화면)
│  ├─ config.js           Firebase 연결 설정, 관리자 UID   ← 2단계, 7단계에서 수정
│  ├─ data/seed.json      Claude에서 만들던 견본 데이터
│  ├─ favicon.ico / favicon.svg / apple-touch-icon.png / icon-*.png / site.webmanifest
│  └─ .nojekyll
├─ firestore.rules        데이터베이스 보안 규칙 (서버의 문지기)  ← 7단계에서 수정
├─ storage.rules          이미지 저장소 보안 규칙                ← 7단계에서 수정
├─ functions/             (선택) 이메일 알림 서버 함수
├─ firebase.json, .firebaserc   Firebase 명령줄 도구용 설정
└─ .gitignore             비밀 파일이 실수로 올라가지 않게 막는 목록
```

## 1. 먼저 알아 둘 보안 구조

GitHub에 올린 코드는 **누구나 볼 수 있다**고 생각해야 합니다. 그래서 이 사이트는 코드를 숨기는 대신, **서버가 문을 지키는 구조**로 만들었습니다.

| 누가 | 무엇을 할 수 있나 | 누가 막나 |
|---|---|---|
| 모든 방문자 | 콘텐츠 보기, 주문하기, 문의 보내기, **자기 주문만** 조회 | Firestore 보안 규칙 |
| 관리자 (지정 UID + 비밀번호 + 인증 앱 코드) | 콘텐츠 수정, 주문과 문의 열람, 이미지 업로드 | Firestore / Storage 보안 규칙 |
| 그 외 (코드를 복사하거나 개발자 도구로 화면을 고친 사람) | 아무것도 바꾸지 못함 | 서버가 요청을 거부 |

**공개되어도 괜찮은 것:** `config.js`의 Firebase 설정값, 관리자 UID, 보안 규칙 파일, 이 README.
Firebase 웹 설정값(apiKey 등)은 "어느 프로젝트에 연결할지" 알려 주는 주소일 뿐이고, 권한은 보안 규칙이 결정합니다.

**절대 올리면 안 되는 것:** 관리자 비밀번호, 서비스 계정 키(`...-firebase-adminsdk-....json`), Gmail 앱 비밀번호, 결제(PG) 비밀키.
`.gitignore`에 대표적인 파일 이름을 넣어 두었지만, 올리기 전에 한 번 더 확인하세요.

## 2. Firebase 프로젝트 만들기와 config.js 채우기

1. https://console.firebase.google.com 에 Google 계정으로 로그인합니다.
   - 이 Google 계정이 사이트 전체의 열쇠가 됩니다. **반드시 2단계 인증을 켜 두세요.**
2. **프로젝트 추가** → 이름 입력(예: `artist-home`) → Google 애널리틱스는 꺼도 됩니다.
3. 프로젝트 화면에서 **웹 앱 추가(</> 모양)** → 앱 이름 입력 → "Firebase 호스팅 설정"은 체크하지 않습니다.
4. 화면에 나오는 `firebaseConfig = { ... }` 값을 복사해서 `docs/config.js`의 `FIREBASE_CONFIG`에 그대로 붙여 넣습니다.
5. `.firebaserc`의 `YOUR_PROJECT_ID`도 같은 프로젝트 ID로 바꿉니다 (11단계를 할 때만 필요).

## 3. 요금제와 예산 알림

이미지 저장소(Cloud Storage)와 이메일 알림(서버 함수)은 Firebase 정책상 **Blaze(종량제) 요금제**에서만 쓸 수 있습니다.
Blaze에도 무료 사용량이 포함되어 있어서, 방문자가 많지 않은 개인 사이트는 대부분 비용이 거의 나오지 않습니다.

1. 콘솔 왼쪽 아래 **요금제 업그레이드** → **Blaze** 선택 → 결제 카드 등록.
2. **예산 알림을 꼭 설정하세요.** Google Cloud 콘솔 → **결제 → 예산 및 알림** → 예: 월 5,000원, 50%·90%·100% 알림.
   - 예산 알림은 "알려 주기"만 하고 자동으로 멈추지는 않습니다. 알림 메일이 오면 콘솔에서 사용량을 확인하세요.

## 4. 로그인 방식 켜기와 관리자 계정 만들기

콘솔 → **Authentication** → **시작하기**

1. **로그인 방법** 탭에서 두 가지를 켭니다.
   - **이메일/비밀번호** — 관리자 로그인용
   - **익명** — 방문자가 회원가입 없이 주문하고 "주문 조회"를 할 수 있게 해 줍니다.
2. **사용자** 탭 → **사용자 추가** → 관리자 이메일과 비밀번호 입력.
   - 비밀번호는 다른 곳에서 쓰지 않는 긴 문장형(예: 16자 이상)을 권합니다.
3. 추가된 사용자 줄의 **사용자 UID**를 복사해 메모해 둡니다. 7단계에서 씁니다.
4. **설정** 탭 → **승인된 도메인**에 나중에 쓸 도메인을 미리 추가해 둡니다.
   - 예: `내도메인.kr`, `www.내도메인.kr`, `내깃허브아이디.github.io`
   - `localhost`는 기본으로 들어 있어 내 컴퓨터에서 시험할 수 있습니다.

## 5. 관리자 2단계 인증(TOTP) 켜기

관리자 로그인에 Google Authenticator 같은 **인증 앱의 6자리 코드**를 추가로 요구하도록 합니다.

1. 콘솔 → **Authentication → 설정** 에서 **Identity Platform으로 업그레이드**를 진행합니다.
   (2단계 인증 기능을 쓰기 위한 단계입니다. 소규모 사이트는 무료 사용량 범위 안입니다.)
2. 프로젝트에 TOTP 방식을 켭니다. 내 컴퓨터에 아무것도 설치하지 않아도 되는 방법입니다.
   1. https://console.cloud.google.com 에서 같은 프로젝트를 고른 뒤, 오른쪽 위 **Cloud Shell 활성화(>_ 모양)** 를 누릅니다.
   2. 아래 명령에서 `내프로젝트ID`만 바꿔 붙여 넣고 실행합니다.

```bash
PROJECT_ID=내프로젝트ID
curl -X PATCH "https://identitytoolkit.googleapis.com/admin/v2/projects/${PROJECT_ID}/config?updateMask=mfa" \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  -H "X-Goog-User-Project: ${PROJECT_ID}" \
  -d '{"mfa":{"providerConfigs":[{"state":"ENABLED","totpProviderConfig":{"adjacentIntervals":5}}]}}'
```

   3. 결과에 `"state": "ENABLED"`와 `totpProviderConfig`가 보이면 성공입니다.

> 인증 앱 등록 자체는 10단계에서 사이트 관리자 화면이 안내합니다.

## 6. 데이터베이스와 이미지 저장소 만들기

1. 콘솔 → **Firestore Database** → **데이터베이스 만들기**
   - 위치: **asia-northeast3 (서울)** 권장. 한 번 정하면 바꿀 수 없습니다.
   - 시작 모드: **프로덕션 모드**
2. 콘솔 → **Storage** → **시작하기** → 같은 위치(서울) 선택 → 프로덕션 모드.

## 7. 관리자 UID 넣고 보안 규칙 적용하기

4단계에서 메모한 UID를 **세 곳에 똑같이** 넣습니다. `YOUR_ADMIN_UID`를 찾아 바꾸면 됩니다.

| 파일 | 역할 |
|---|---|
| `docs/config.js` → `ADMIN_UIDS` | 화면에 관리자 메뉴를 보여 줄지 판단 (표시용) |
| `firestore.rules` → `isAdmin()` | **실제 권한** — 데이터 수정, 주문/문의 열람 |
| `storage.rules` → `isAdmin()` | **실제 권한** — 이미지 업로드 |

규칙 적용 (명령줄 도구 없이 콘솔에서):

1. 콘솔 → **Firestore Database → 규칙** 탭 → 내용을 모두 지우고 `firestore.rules` 전체를 붙여 넣기 → **게시**.
2. 콘솔 → **Storage → 규칙** 탭 → `storage.rules` 전체를 붙여 넣기 → **게시**.

> 관리자를 바꾸거나 추가할 때도 이 세 곳을 함께 고치고, 규칙을 다시 게시해야 합니다.

## 8. GitHub에 올리고 공개하기

1. GitHub 계정에 **2단계 인증**을 켭니다 (Settings → Password and authentication).
2. 새 저장소를 만듭니다 (예: `artist-home`).
   - 무료 계정에서 GitHub Pages를 쓰려면 저장소가 **Public**이어야 합니다. 1번 보안 구조대로 공개되어도 안전하게 만들어져 있습니다.
3. 이 폴더의 파일을 모두 올립니다. (웹에서 **Add file → Upload files**로 끌어다 놓아도 됩니다.)
   - 올리기 전에 서비스 계정 키(.json)나 비밀번호가 적힌 파일이 섞여 있지 않은지 확인하세요.
4. 저장소 **Settings → Pages**
   - Source: **Deploy from a branch**
   - Branch: **main**, 폴더: **/docs** → Save
5. 1~2분 뒤 `https://내아이디.github.io/artist-home/` 에서 사이트가 열리는지 확인합니다.

**내 컴퓨터에서 먼저 시험하고 싶다면:** `docs` 폴더에서 `python3 -m http.server 8000` 을 실행하고 http://localhost:8000 을 엽니다.
(파일을 더블클릭해서 여는 방식은 브라우저 보안 때문에 작동하지 않습니다.)

## 9. 전용 도메인 연결하기

1. 도메인 구매처(가비아, 후이즈, Cloudflare 등)의 **DNS 관리**에서 아래 레코드를 추가합니다.

| 종류 | 호스트(이름) | 값 |
|---|---|---|
| A | @ (비워 두기) | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | `내아이디.github.io` |

2. GitHub 저장소 **Settings → Pages → Custom domain**에 `www.내도메인.kr`(또는 `내도메인.kr`) 입력 → Save.
   - GitHub가 `docs/CNAME` 파일을 자동으로 만듭니다. 지우지 마세요.
3. DNS가 퍼지면(몇 분~최대 하루) **Enforce HTTPS**를 체크합니다.
4. 4단계의 Firebase **승인된 도메인**에 실제 도메인이 들어 있는지 다시 확인합니다.
5. 도메인 구매처 계정에도 **2단계 인증**을 켜 두세요. 이 계정이 털리면 사이트 주소 자체를 빼앗길 수 있습니다.

**(권장) API 키 사용처 제한:** Google Cloud 콘솔 → **API 및 서비스 → 사용자 인증 정보** → "Browser key" →
**웹사이트 제한**에 `https://내도메인.kr/*`, `https://www.내도메인.kr/*`, `https://내아이디.github.io/*`, `http://localhost:*` 를 추가합니다.
다른 사이트가 내 설정값을 가져다 쓰는 것을 막아 줍니다. 저장 후 로그인과 주문이 정상인지 꼭 확인하세요.

## 10. 첫 로그인과 견본 데이터

1. 사이트 맨 아래 풋터의 **관리자**를 누릅니다.
2. 4단계에서 만든 이메일과 비밀번호로 로그인합니다.
   - "관리자 계정이 아니에요"가 나오면 화면에 보이는 UID가 7단계의 세 곳에 정확히 들어갔는지 확인하세요.
3. **2단계 인증 등록** 화면이 나옵니다.
   - 휴대폰에 Google Authenticator(또는 Microsoft Authenticator)를 설치합니다.
   - 화면의 QR 코드를 찍고, 앱에 나온 6자리 숫자를 입력합니다.
   - **등록이 끝나면 로그아웃 후 다시 로그인**해야 관리자 화면이 열립니다. 이제부터는 비밀번호 + 6자리 코드로 들어갑니다.
4. 관리자 화면 → **보안, 계정** → **견본 데이터 불러오기**를 누르면 Claude에서 만들던 견본이 들어옵니다.
   - 모두 "(예시)" 표시가 된 견본입니다. 실제 내용으로 바꿔 주세요.
5. **무용가 정보**에서 이름, 프로필 사진, 이력, 입금 계좌, 사업자 정보, 개인정보처리방침을 채웁니다.
6. **메타 태그**에서 제목과 설명을 정한 뒤, 생성된 코드를 `docs/index.html`의 `<head>` 맨 위 기본 메타 태그 자리에 바꿔 붙여 넣고 다시 올립니다.
   (카카오톡 링크 미리보기, 네이버 검색은 이 코드를 읽습니다.)

> 휴대폰을 잃어버리거나 바꾸면 인증 앱 코드를 받을 수 없습니다. 콘솔 → Authentication → 사용자에서 해당 계정의 2단계 인증을 해제한 뒤 새 휴대폰으로 다시 등록하세요.
> (이 해제 권한이 1번에서 말한 "Google 계정이 사이트의 열쇠"인 이유입니다.)

## 11. (선택) 새 주문, 문의 이메일 알림

새 주문이나 문의가 들어오면 관리자 메일로 내용을 보냅니다. 명령줄 도구가 필요합니다.

준비물: Node.js 20 (https://nodejs.org), Gmail 계정(2단계 인증 켜져 있어야 함)

1. Gmail 계정 → **Google 계정 관리 → 보안 → 앱 비밀번호**에서 16자리 앱 비밀번호를 만듭니다.
2. 터미널에서 이 폴더로 이동한 뒤:

```bash
npm install -g firebase-tools
firebase login
cd functions && npm install && cd ..
firebase functions:secrets:set GMAIL_APP_PASSWORD   # 1번의 16자리 입력 (화면에 표시되지 않음)
firebase deploy --only functions
```

3. 배포 중 `GMAIL_USER`(보내는 Gmail 주소)와 `NOTIFY_TO`(받을 주소)를 물어보면 입력합니다.
   - 입력값은 `functions/.env.프로젝트ID` 파일에 저장됩니다. `.gitignore`에 들어 있으니 GitHub에는 올라가지 않습니다.
4. 사이트에서 시험 문의를 보내 메일이 오는지 확인합니다.

> 앱 비밀번호는 서버 비밀 저장소(Secret Manager)에만 보관되고 코드나 저장소에는 남지 않습니다.
> 카카오톡 알림이 필요해지면 같은 함수에서 알림톡 발송 대행사 API를 호출하도록 확장할 수 있습니다.

## 12. 파비콘 바꾸기

지금 들어 있는 파비콘은 '舞' 글자로 만든 임시 이미지입니다.

1. 정사각형 로고 이미지(512×512 이상 PNG 또는 SVG)를 준비합니다.
2. https://realfavicongenerator.net 같은 생성기에 올려 파일 묶음을 받습니다.
3. `docs/` 안의 같은 이름 파일을 바꿔치기합니다: `favicon.ico`, `favicon.svg`, `apple-touch-icon.png`, `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`
4. 브라우저는 파비콘을 오래 기억하므로, 바뀐 모습은 새 창이나 시크릿 창에서 확인하세요.

## 14. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| "사이트 설정(config.js)이 아직 완료되지 않아…" | 2단계의 `FIREBASE_CONFIG` 값 |
| 콘텐츠가 비어 있음 | 6단계 데이터베이스 생성, 7단계 규칙 게시, 10단계 견본 데이터 |
| 주문·문의 전송 실패 | 4단계 **익명** 로그인 켜기, 7단계 규칙 게시 |
| "관리자 계정이 아니에요" | 화면의 UID가 세 곳에 정확히 들어갔는지, 규칙을 다시 게시했는지 |
| 관리자 화면에서 저장 실패 | 2단계 인증 등록 후 다시 로그인했는지, 규칙의 UID |
| "TOTP 2단계 인증이 아직 켜지지 않았어요" | 5단계 Identity Platform 업그레이드와 Cloud Shell 명령 |
| 도메인에서 로그인 오류 | 4단계 **승인된 도메인**, 9단계 API 키 제한 목록 |
| 이미지 업로드 실패 | 3단계 Blaze 요금제, 6단계 Storage 생성, 7단계 storage.rules 게시 |

자료출처 페이지의 전통춤 설명은 공공기관 자료(확인일 2026.10.04)를 요약한 것입니다. 기관 누리집 내용이 바뀌면 `docs/index.html`의 `SRC` 목록과 본문을 함께 고쳐 주세요.
